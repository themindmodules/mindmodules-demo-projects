# 24-hour plan

| Hours | Goal | Done when |
|---|---|---|
| 0-1 | Pick the problem, split roles, create the repo | Everyone has the repo and knows their task |
| 1-4 | Data path: simulator (or real sensor) to CSV | `telemetry.csv` exists |
| 4-8 | Detectors in `analyze.py`, test on injected faults | Events list matches what you injected |
| 8-12 | Dashboard: charts and event table | Opens from `file://`, looks clean |
| 12-14 | Break and sleep in shifts. Do not skip this. | Team is functional again |
| 14-18 | Hardware (if any): ESP32 reading a sensor, sending rows | One real row appears in the CSV |
| 18-20 | Pitch deck (6 slides) and demo rehearsal | Two full run-throughs with a timer |
| 20-22 | Bug fixing only. Feature freeze at hour 20. | No new features |
| 22-23 | Final rehearsal, backups (video of the demo, screenshots) | Backup video recorded |
| 23-24 | Submit, charge laptops, test the projector adapter | Submission confirmed |

## Rules that save hackathons

1. **Feature freeze at hour 20.** Late features break demos.
2. **Record a backup demo video** at hour 22. Venue Wi-Fi fails.
3. **One person owns the pitch.** Others feed them facts, not slides.
4. **Commit often.** If a laptop dies, you still have the repo.
